# 身体日常记录

这是完整的静态单页 PWA，包含吃饭、喝水、排便、体重、喝酒五类记录。无需安装依赖，无需数据库，无需业务服务器。所有图表、图标与代码都在本地文件中，无 CDN 依赖。

首次安装需要将这些静态文件放到可访问的 HTTPS 网站，浏览器才能下载并缓存；之后可断网打开、保存记录。这里的“无需服务器”是无需自行运行后端，手机首次获取网页仍需要静态托管。直接双击 HTML 或把文件发送给 iPhone，不能完成 PWA 安装与离线缓存。

## 功能与使用

- 吃饭：填写时间、食物名称、份量、备注。内置 35 种常见食物参考值；输入名称时可从候选列表选择。单位支持克或该食物的参考份量，表单会显示一份有多少克。自定义食物使用克并手动填热量。可以直接修改估算热量，也可点“恢复自动估算”。
- 喝水：记录 ml；今日和近七天饮水量自动相加。酒类饮用量不计入喝水量。
- 排便：五种性状、腹痛与否、备注；统计每日次数。
- 体重：记录 kg、时间、备注；图中显示近七天每日最后一次称重。缺失日期断开连线，不补零。
- 喝酒：选择酒类参考，填写酒名、饮用量、酒精度、碳水含量和备注。自动估算热量，可手动改。参考类型有啤酒、葡萄酒、白酒、烈酒、黄酒、鸡尾酒及自定义。
- 记录按时间倒序排列，五类颜色区分；单条删除前有确认。
- 今日摄入热量 = 食物热量 + 酒类热量。最近七天包含今天及前六个本地自然日。
- CSV 导出全部日期的记录，包含原始字段、UTC 时间和当前时区下的本地时间。UTF-8 BOM 便于表格软件识别中文；字段正确处理逗号、引号和换行，可能被当成公式的文本会加前置单引号。

## 热量怎么算

食物总热量（千卡）= 可食部分重量（克）× 每 100 克参考热量 ÷ 100。

酒类总热量（千卡）≈ 饮用量（ml）× 酒精度 ÷ 100 × 0.789 × 7 + 饮用量（ml）÷ 100 × 碳水含量（克 / 100 ml）× 4。

- `0.789` 是计算采用的乙醇密度近似值（克 / ml）。
- 酒精约 7 千卡 / 克，碳水约 4 千卡 / 克。
- 碳水含量包含糖，不能再把同一份糖重复加一次。
- 例如 330 ml、5% vol、碳水 3.5 克 / 100 ml 的啤酒，估算为 137.3 千卡。
- 50 ml、52% vol、碳水为 0 的白酒，估算为 143.6 千卡。
- 鸡尾酒使用整杯饮用量与混合后的最终酒精度。糖浆、果汁等计入碳水，奶油等脂肪成分没有在这个公式中自动估算，应手动填写总热量。
- 食物库和酒类默认值是粗略参考，不是特定品牌的营养数据库；优先按包装标签修正。表单热量保留一位小数。
- 手动修改热量后，更改份量仍保留手动值；需要重新估算时点“恢复自动估算”。切换酒类参考会重新采用该参考的自动估算。

能量换算参考：[NIAAA 酒精能量说明](https://arcr.niaaa.nih.gov/media/566/download?inline=)。酒精与碳水的能量系数用于估算；这里的预设份量和各酒类碳水值是可修改的产品参考值。

## 部署到 GitHub Pages（无需命令行）

1. 在电脑上解压源码压缩包，打开“身体日常记录”文件夹，确认能看到 `index.html`、`sw.js` 和 `icons` 等文件。
2. 打开 [GitHub](https://github.com/)，注册或登录，创建一个新的公开仓库，例如 `body-daily`。初始化一个说明文件也可以。
3. 在仓库中点“添加文件（Add file）→ 上传文件（Upload files）”。上传应用文件夹里面的全部内容，保留 `icons` 子文件夹。必须让 `index.html` 直接位于仓库根目录，不要再套一层“身体日常记录”目录，也不要只上传 ZIP。
4. 提交文件。进入仓库“设置（Settings）→ Pages”。
5. 在“构建和部署（Build and deployment）”下，把发布来源设为“从分支部署（Deploy from a branch）”。选择 `main` 分支和根目录 `/ (root)`，保存。
6. 等待发布完成，在 Pages 页面打开生成的网址，一般为 `https://你的用户名.github.io/body-daily/`。使用页面实际给出的网址；确保地址是 HTTPS。
7. 如果可选，打开“强制 HTTPS（Enforce HTTPS）”。打开应用后等待右上角出现“离线已就绪”。
8. 首次无记录属于正常状态。可以先添加一条测试记录，再刷新确认仍在。若网页显示 404，检查 Pages 部署状态、分支与 `index.html` 所在位置。

代码使用相对路径，因此支持 GitHub Pages 的仓库子路径部署。更换部署域名或浏览器不会自动迁移已有记录。

官方依据：[创建 GitHub Pages 网站](https://docs.github.com/en/pages/getting-started-with-github-pages/creating-a-github-pages-site)、[配置发布来源](https://docs.github.com/en/pages/getting-started-with-github-pages/configuring-a-publishing-source-for-your-github-pages-site)。

## iPhone 安装到桌面

1. 把已经部署的 HTTPS 网址发到 iPhone，在 **Safari 浏览器**中打开，使用普通浏览模式。
2. 等待顶部显示“离线已就绪”。
3. 点 Safari 的分享按钮。如果当前布局把分享操作收在“更多”中，先打开“更多”。
4. 选择“添加到主屏幕”。找不到时，在分享菜单底部的“编辑操作”中添加这个操作。
5. 如果出现“作为网页 App 打开”开关，请保持开启；应用名称可以保留“身体日常记录”。点“添加”。
6. 返回桌面，点绿色“日”字图标启动。再联网打开一次，等待“离线已就绪”，以后固定从这个桌面图标记录。
7. 开启飞行模式并关闭 Wi-Fi，退出应用再从桌面图标打开。确认页面正常显示，试着保存一条喝水记录，然后重新打开检查记录仍在。

iPhone 会以独立网页 App 的方式启动，不显示 Safari 地址栏。系统状态栏、主屏幕指示条是否保留由 iOS 决定，网页无法保证像原生游戏那样隐藏所有系统界面；项目已配置全屏请求及独立模式兼容信息。iPhone 不依赖安卓的自动安装弹窗，使用“添加到主屏幕”。

官方依据：[Apple：在 iPhone 上将网站变为 App](https://support.apple.com/zh-cn/guide/iphone/iphea86e5236/ios)、[MDN：PWA 安装条件](https://developer.mozilla.org/en-US/docs/Web/Progressive_web_apps/Guides/Making_PWAs_installable)。

## 数据与备份

数据存储键为 `body-daily-records-v1`，内容为带版本号的 JSON。`localStorage` 保存个人记录；service worker 的 Cache Storage 只缓存应用文件，两者用途不同。没有登录、云同步、广告或第三方追踪脚本。

浏览器、桌面 App 和不同站点之间的数据可能隔离。不要假设在 Safari 填过的数据一定会出现在桌面 App 中，建议安装后从桌面开始正式记录。清除网站数据、删除重装或系统存储回收可能导致数据丢失。请定期导出并把文件保存到“文件”App；导出的个人 CSV 不要上传到公开代码仓库。

在 iPhone 点“导出 CSV”后，如弹出系统分享面板，选择“存储到文件”；如果采用下载方式，请在 Safari 下载列表或“文件”的下载目录查找。取消分享不会删除任何记录。本版 CSV 是可读备份，**没有自动导入恢复功能**。

若存储已满或被禁止，页面会提示“保存失败”，表单不清空，不会伪装成保存成功。若读取的数据已损坏，会停止覆盖原存储，需先保留原始数据再处理。

## 更新应用

1. 替换需要更新的源文件。
2. 将 `sw.js` 中缓存版本从 `v1` 改为 `v2`，后续更新继续递增。
3. 上传文件到同一部署位置。
4. 用户联网打开后，浏览器下载新的完整缓存。关闭该应用的所有窗口和相关 Safari 标签，再重新打开以启用新版。
5. 缓存升级不会主动删除 `localStorage` 里的记录。不要随意更改存储键或数据结构。
